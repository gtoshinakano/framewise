# Shot keyframe selection

`POST /api/episodes/{id}/keyframe-selection` queues CPU work for all active cuts. The optional JSON body is `{"settings": {}}`; `GET` at the same path returns the latest job status and current or stale cached result for each active cut. A failed or cancelled job can be retried through the standard job retry endpoint. Restart or recreate the API container after installing its new Python dependencies.

Each result identifies decoded frames by their source and cut-relative zero-based ordinals, episode-relative presentation timestamp, and cut-relative timestamp. Change scores are indices from 0 to 100, not movement percentages. The shot score combines peak global, regional and accumulated changes, detected-event frequency and peak spatial coverage. The frame score weights global, regional and accumulated change by 0.35, 0.35 and 0.30. Regional change is the larger of the 90th percentile of tile differences and 70% of their maximum; per-tile and global differences are normalized by 12 grayscale levels by default. An event that exceeds the frame budget is reported in `coverage_limited` and `uncovered_events`; these refer to detected events, not semantic ground truth.

The latest completed subtitle extraction supplies the masked horizontal band. Without a valid band the default mask is the bottom 20%; its bounds are configurable with `mask_top` and `mask_bottom` as frame-height fractions. The mask is applied before blurring as well as to scoring, so text at its edge cannot bleed into metrics. All movement inside the band is ignored too; subtitles outside the fallback band can still influence selection. Extracting subtitles later changes the mask and invalidates the cache. Original-resolution images are not altered or stored by this job.

Settings include `longest_edge` (640), `grid` (4), `normalization` (12), `event_threshold` (0.15), `novelty_threshold` (0.12), `state_novelty_threshold` (0.06), `budget` (15, maximum 15), `blur` (3), `ssim_low` (0.10), `ssim_high` (0.22), `ssim_threshold` (0.995), and the three frame score weights. Thresholds are initial values, not calibrated guarantees. The strongest 64 event candidates per shot are retained; omitted events count as uncovered.

For evaluation, annotate meaningful event intervals and visual states across static, facial, gradual, sudden, camera-motion, return-to-start, short and complex shots. Compare selected timestamps against five uniformly timed frames from the same shots. Report event recall and misses, selected-frame redundancy, temporal coverage, average selection count, runtime and memory. Compare downstream descriptions against the same annotations with identical prompts. Track cases where masking obscures real action separately. Run a full-episode benchmark on the target CPU before claiming the 60–120 second target or tuning thresholds.

The selector retains additional visual states during sustained image change. State novelty uses the maximum of the global and regional grayscale differences normalized by 255, before the change-score normalization saturates. The newest representative becomes the reference when the configurable state threshold is crossed. At most 64 time-spread state candidates are retained alongside event candidates; selection compares these with the frames already chosen. `visual_state` identifies frames selected for this reason.

The maximum is five frames per started five-second window, capped at 15 for the whole cut and further restricted by `budget`. Windows start at the cut boundary and are half-open: a frame exactly five seconds into the cut belongs to the second window. Every window, including those after 15 seconds, permits at most five selected frames. Duration establishes an upper limit only, so visually static shots still select one frame. `coverage_limited` also warns when a frame or window limit leaves meaningful retained states unrepresented; it is an estimate, not a semantic guarantee. Existing queued jobs keep their recorded budget, and changing the algorithm version invalidates earlier cached selections.

The Target frames tab shows the current selected-frame count. Thumbnail requests seek to a uniquely verified presentation timestamp when possible and fall back to decoded source-frame ordinal when the timestamp is ambiguous. Thumbnails use the shared bounded, short-lived memory cache; temporary extraction files are cleaned up, and no thumbnail files are stored in the project or beside the source video.

People on the selected frames are found by a separate job, not by this selector. `POST /api/cuts/{id}/target-detection` (or `POST /api/episodes/{id}/target-detection`) queues it for cuts that have a current evaluation; results are read with `GET /api/cuts/{id}/target-detections`. Each result belongs to the evaluation it was made for: evaluating the cut again deletes it when the selected frames change, and keeps it when the evaluation is unchanged.
