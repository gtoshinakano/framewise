## Why not just take the recommended option

The reviewer (Qwen 3.6 with pictures) already marks one option as recommended. Against the user's own answers on the 74
Episode 2 cuts they answered (112 questions with a recommendation), it agrees **69%**, far under the 90% bar (D12):

| topic | agrees with the user |
|---|---|
| gaze | 9/10 (90%) |
| identity | 5/5 |
| speaking | 39/58 (67%) |
| pose | 11/18 (61%) |
| emotion | 4/6 |
| state | 7/13 (54%) |

The disagreements are systematic (all 35 listed in the replay report):

- **Speaking, from line strips** (12 of 37): the reviewer reads a mouth as closed in a four-tile strip and recommends an
  inner voice; the user keeps the visible speaker lip-synced. Exceptions the user made: back to the camera, too far, not
  visible (then off-screen or narrative, "no lip-sync").
- **Speaking, timing** (4): the reviewer trusts the transcript's start time; the user takes the beats' (the line bled
  across a hard cut: M3 removes most of these), or says the cut has no voice at all.
- **A picture from another shot** (4): a last keyframe that shows the next shot is a missed hard cut, not a change
  ("The side view is a hardcut and must be ignored"); M2 removes these.
- **Pose/state** (13): mixed; the user often sides with the first-frame description over a picture reading.

So the agent cannot apply the reviewer's choice alone, and the local model alone is unmeasured. M4 is built to apply
only what is measured or ruled, and to measure the rest.

## How it decides

1. **Local decider** (job `review_decisions`, one per cut, text lane, local or remote server): reads the evidence the
   answers prompt reads (`review_answers.build_evidence`) plus the questions, the user's **standing rules** for those
   topics and the project notes. Grammar-constrained, one decision per question: `choice` (option id or null), `kind`
   (`fact` | `creative`), `confidence` (`high|medium|low`), `rule` (a standing rule decides it), `reason`. The prompt names
   the weak evidence above so it does not give high confidence on it.
2. **Resolver** (`resolve`, pure):
   - a standing rule decides it with high confidence → **apply** (tier `local`);
   - a creative question no rule covers → **person**;
   - the decider agrees with the recommended option, high confidence, and the topic's **trust** ≥ 90% → **apply**;
   - otherwise the topic's *when unsure*: `recommended` → apply the recommended option (tier `rules`); `ask` → person;
     `evidence` → **Claude** while the run's Claude budget lasts (one item per cut), else person;
   - the profile's mode `ask` turns every apply into a question for the person; `off` queues nothing.
   A question whose line is already in *Your answers* is kept (`selection`, the UI's own rule ported from
   `consistencyView.ts`).
3. **Trust** (`trust_table`, per project and topic): the share of shadow decisions that agreed with the reviewer at high
   confidence and match the user's own answer, once a topic has 10; before that, how often the user took the
   recommended option (a lower bound); fewer than 10 → untrusted. Answers the agent wrote are never counted as the user's.
4. **Escalations** (`review_question`, one per cut and reviewer: `cut:<id>:claude`, `cut:<id>`): the questions, the
   decider's proposal and reason, why it was asked, the pictures its `why` cites, and a sheet URL. Answered through
   `POST /api/escalations/{id}/review-answers {answers: [{question, option|text}], unsure, tier, note, run_id}`: Claude
   picks option ids only, its `unsure` and unanswered questions move to the person's item with its note; the person may
   write text. They close themselves when the review is written again (dismissed) or every question has an answer
   (resolved; also when the person answers in the Results tab: the `PUT brief-instructions` route calls `close_settled`).
5. **Writing**: `apply_answers` writes one `- Topic (Character): option text` line per answer with
   `review_answers.save_hand_answers` (Cut summary stale, drafts stale, a running auto-save draft job keeps them) and one
   `agent_decisions` row per cut and tier (kind `review_answers`, target `cut_brief_instructions`, before/after content
   and the lines with the decider's reading). Undo (`agent_log.UNDO_KINDS['review_answers']`) restores the content while it
   is still what the agent wrote; a person's save marks the decision overridden.

**Shadow runs** (`fw review-decisions run EP --shadow`) take only cuts whose current review the user answered, decide
with their answers hidden, and write nothing but a `review_decisions` row (no answers, no escalations, no stale marks;
scope writes nothing, so they are safe on sequenced cuts). That is the measurement; `trust_table` reads it.
