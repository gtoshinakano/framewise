# M6: characters that matter (built 2026-11-22)

Code: `backend/app/character_decisions.py` (job kind `character_decisions`, CPU, media lane, API process), routes in
`character_decisions_api.py`, `scripts/fw cast`, skill `.agents/skills/framewise-cast/`, replays
`autopilot/replay/box_names.py` and `autopilot/replay/target_frames.py`, tests `tests/test_character_decisions.py`.

No model is loaded: the job reads what recognition and the target-frame tracker stored (`candidates_json`, the CCIP
vectors in `character_detection_embeddings`, `target_detection_runs.frames_json`/`candidates_json`) and the keyframe
analysis's per-frame states.

## Rules

| Item | Applied by a rule | Claude (sheet) | The person |
|---|---|---|---|
| Unnamed first-frame box | shortlist leader ≥ 0.72 with a 0.10 lead, or ≥ 0.58 with a 0.08 lead when the same character is boxed in the cut before or after (≥ 0.48 for a character the profile says *always matters*) | leader ≥ 0.50 but not clear; best match already boxed in the cut; look-alike pair within 0.15 | when the Claude budget is spent or Claude is off |
| Second box over a named person (IoU ≥ 0.7) | removed | | |
| Box whose leader the profile calls *background* | removed | | |
| Automatic label (`auto`) | **never** | up to 12 boxes per character per sheet, least sure first, with what the budget leaves after the gates | not asked (not a gate); bulk confirm from the inbox |
| Unknown person (leader < 0.50) | grouped by CCIP vector (cosine ≥ 0.82 to the group mean); one small appearance → unboxed as background | in between (*borderline*) | matters: 3+ cuts, a box ≥ 45% of the frame height, or two cuts ≥ 25% |
| Flagged target frame | headcount dropped and the keyframe states say exactly those people left the picture; or the only flag is an extra crop fitting no colour while everyone from the opening frame is still boxed | other flags of the cut, one question per cut | unnamed colours, and what Claude hands on |

Agent labels are `label_source='agent'`: `anime_gallery` reads only `manual`, so they are never gallery examples (D10),
and a recognition re-run (`anime_bulk._save_recognition`) clears only `auto`/empty labels, so they stay. Only the
person's own answer writes `manual` (the representative box of a named group; every box they confirm on a sheet).
A reviewed target frame changes no box, so nothing turns stale; a label change or removed box goes through
`structured_results.opening_box_edited` like a hand edit.

## Replay (2026-11-22, all episodes, copy of the live database)

- **Box names** (`box_names.py`): 305 boxes the user labelled by hand that have a stored shortlist, label hidden.
  Named 80/84 right (95.2%, the D12 bar); 220 asked, 1 unknown, 0 removed (duplicate IoU raised from 0.5 to 0.7 after
  three removals of boxes the user kept). The four wrong names are listed in the report.
- **Why automatic labels are never confirmed by a rule:** on the same boxes, the leader at ≥ 0.80 with a 0.06 lead was
  the user's label 49/72 times (68%). The sample is biased toward labels the user corrected, but no bar reached 95%.
- **Target frames** (`target_frames.py`): 95 frames marked reviewed by the two rules (87 extra crop, 8 left the
  picture), none of them corrected by the user afterwards (21 the user had also marked reviewed themselves).
