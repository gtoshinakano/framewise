# External integration guide

Framewise is a local-first video analysis service. The OpenAPI document is at `/openapi.json`, interactive Swagger UI at `/docs`, and this guide as Markdown at `/api/integration-guide`. Resolve all paths in this guide against the Framewise server origin, for example `http://192.168.0.6:8080`. The listening address may differ on your installation. No authentication is required on this trusted network. Treat the server as the source of truth; do not guess IDs or assume a title is unique.

## Data relationships and units

A **project** contains **episodes**; each episode has one preserved original video. Preparation extracts metadata, a proxy, audio if present, and frames. The user triggers hard-cut detection, which creates **cuts** on the episode timeline. A cut has a UUID, `episode_id`, zero-based `cut_index`, `start_time`, and `end_time`: `CUT1` conventionally means the active cut with `cut_index` 0, not index 1. IDs are UUID strings, titles are labels, timestamps and durations are seconds from episode start, and a cut covers `[start_time, end_time)`. Cuts can be edited, archived, reactivated, reordered or merged: keep the cut UUID and refresh its current metadata before use. Archived cuts have `active=false` and negative indices; they are not in the current timeline. A cut may cross a **chunk** boundary; chunks are independent working segments, not visual cuts.

A cut has editable notes, an `analysis_enabled` flag for future queued visual analysis, and zero or more **analysis results**, each with a `kind`, title, content, origin and optional model, job, prompt, settings and input context provenance. Disabling a cut does not change already queued snapshots or existing results. Analysis is not automatically available for every cut. Results are revision chains: `parent_id` points back and `superseded_by` points forward. Default reads and cut detail return current revisions; `history=true` returns all revisions. All current results are usable in analysis and summary regeneration. Use origin and provenance and review content where accuracy matters. `cut.results` is a separate legacy editable field, not the revisioned results list. `context` and `settings` contain model-specific JSON and may be empty; preserve unknown keys.

For clients explicitly authorized to edit results, `POST /api/cuts/{cut_id}/analysis-results` creates a result and `PUT /api/analysis-results/{result_id}` appends a human revision. Results have no approval status. Editing an already superseded revision returns 409. Deleting an individual current revision restores its parent as current when one exists.

**Context items** are project-wide when `episode_id` is null, otherwise episode-specific. Items include character, world, scenario, object, chapter, and general notes. **Transcript segments** have episode-relative time ranges, text, a deletion marker, and optionally `character_context_id`, linking to a character context item. Default episode transcript reads and cut detail include current non-deleted segments; segments can extend outside the cut. `history=true` on transcript returns all revisions including deleted. A **voice sample** links to a character through `character_context_id`; it can come from uploaded audio or one or more episode ranges. `preview_available` indicates whether its reference audio is currently available. Match IDs, not names. Its WAV reference is not necessarily a transcript of the cut.

## Recommended read sequence

1. Check `GET /api/health`. List `GET /api/v1/projects`, select the project by ID, then `GET /api/v1/projects/{project_id}/episodes` and select an episode by ID. Duplicate names are possible. Read `GET /api/v1/episodes/{episode_id}` for duration, dimensions, status, and `has_audio` (null before probing). Preparation or detection may still be running or failed. Check `GET /api/episodes/{episode_id}/status` for current job state.
2. List `GET /api/v1/episodes/{episode_id}/cuts?offset=0&limit=100`; follow `next_offset` until null. Active cuts only are returned by default. Use `include_archived=true` to include archived cuts after active ones. For CUT1 select the active item with `cut_index=0`. Pagination reflects live data and can shift if cuts are edited while paging; repeat the read if a consistent snapshot matters.
3. Call `GET /api/v1/cuts/{cut_id}`. It includes project and episode metadata, the cut, current analysis results, applicable context, overlapping transcript and chunks, adjacent cuts, project voice samples and relative links to media and further reads. Empty arrays mean no matching data is currently available, not that analysis succeeded. The response is a convenience aggregation rather than a transactionally consistent snapshot: refresh when editing is concurrent.
4. For full result revision history call `GET /api/cuts/{cut_id}/analysis-results?history=true`; the default is current revisions. Set `include_context=false` to omit potentially large captured evidence. For full transcript use `GET /api/episodes/{episode_id}/transcript` (or `?history=true`). `GET /api/cuts/{cut_id}/analysis-context` also supplies current results from neighboring cuts. `GET /api/projects/{project_id}/context` returns all project and episode-scoped context items; filter `episode_id` yourself when needed. `GET /api/cuts/{cut_id}/analysis-config` shows the current analysis settings. Job IDs in results or the episode's jobs list can be passed to `GET /api/v1/jobs/{job_id}` to inspect the queued input snapshot and any retained intermediate cut evidence. Snapshots can be large, can represent older data, and do not imply a job succeeded.
5. To fetch a character's reference, find a matching `character_context_id` in `voice_samples`, check `preview_available`, then download `GET /api/voice-samples/{sample_id}/audio`. `GET /api/v1/voice-samples/{sample_id}` also returns metadata and the stored model-specific voice embedding. Do not assume every character has a sample. To obtain cut audio, use `GET /api/v1/cuts/{cut_id}/audio?before=1&after=3`. This returns prepared mono 16 kHz PCM WAV from the original's first audio stream, with up to one second before and three seconds after the cut. Each margin is non-negative and at most 3600 seconds. The excerpt is clipped to the episode and available audio; `X-Audio-Start-Seconds` and `X-Audio-End-Seconds` are the actual sample-aligned episode timestamps. Archived cuts can also be requested. No audio, not-yet-prepared audio, or unavailable files return 404; an excerpt with no samples or invalid prepared audio returns 409; an excerpt exceeding WAV size limits returns 413. Do not assume silent video has an audio file.
6. Download `GET /api/cuts/{cut_id}/frame/first` or `/last` for cut boundary JPEGs. `GET /api/analysis-results/{result_id}/frame` provides the sampled analysis image when one exists, following its parent chain. Original, proxy, or prepared whole-episode audio can be fetched through `GET /api/episodes/{episode_id}/media/original`, `/proxy`, or `/audio`. `GET /api/episodes/{episode_id}/frames` lists interval frames, and `/waveform` returns waveform data. The existing `GET /api/episodes/{episode_id}` also returns all active and archived cuts, chunks, job metadata, and preparation settings; it can be large.

## Example

```sh
BASE=http://192.168.0.6:8080
curl "$BASE/api/v1/projects"
curl "$BASE/api/v1/projects/PROJECT_UUID/episodes"
curl "$BASE/api/v1/episodes/EPISODE_UUID/cuts?limit=100"
curl "$BASE/api/v1/cuts/CUT_UUID"
curl "$BASE/api/cuts/CUT_UUID/analysis-results?history=true"
curl -OJ "$BASE/api/v1/cuts/CUT_UUID/audio?before=1&after=3"
curl -o voice.wav "$BASE/api/voice-samples/VOICE_SAMPLE_UUID/audio"
```

Replace placeholders with returned IDs and quote URLs containing `&`. JSON errors use `detail`; HTTP 404 means the requested object or media is absent, 409 indicates a state conflict, and 422 indicates invalid parameters. Available data and URLs can change after edits, deletion, or reruns. Media downloads can be large. Polling and caching clients should retry according to their own needs and respect failed job states. The `/api/v1` integration endpoints are read-only; the existing `/api` also contains mutating endpoints. Do not invoke mutations unless explicitly requested.
