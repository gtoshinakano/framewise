# External integration guide

Framewise is a local-first video analysis service. The OpenAPI document is at `/openapi.json`, interactive Swagger UI at `/docs`, and this guide as Markdown at `/api/integration-guide`. Resolve all paths in this guide against the Framewise server origin, for example `http://192.168.0.6:8080`. The listening address may differ on your installation. No authentication is required on this trusted network. Treat the server as the source of truth; do not guess IDs or assume a title is unique.

## Data relationships and units

A **project** contains **episodes**; each episode has one preserved original video. Preparation extracts metadata, a proxy, audio if present, and frames. The user triggers hard-cut detection, which creates **cuts** on the episode timeline. A cut has a UUID, `episode_id`, zero-based `cut_index`, `start_time`, and `end_time`: `CUT1` conventionally means the active cut with `cut_index` 0, not index 1. IDs are UUID strings, titles are labels, timestamps and durations are seconds from episode start, and a cut covers `[start_time, end_time)`. Cuts can be edited, archived, reactivated, reordered or merged: keep the cut UUID and refresh its current metadata before use. Archived cuts have `active=false` and negative indices; they are not in the current timeline. A cut may cross a **chunk** boundary; chunks are independent working segments, not visual cuts.

A cut has editable notes, an `analysis_enabled` flag for future queued visual analysis, and zero or more **analysis results**, each with a `kind`, title, content, origin and optional model, job, prompt, settings and input context provenance. Disabling a cut does not change already queued snapshots or existing results. Analysis is not automatically available for every cut. Results are revision chains: `parent_id` points back and `superseded_by` points forward. Default reads and cut detail return current revisions; `history=true` returns all revisions. All current results are usable in analysis and summary regeneration. Use origin and provenance and review content where accuracy matters. `cut.results` is a separate legacy editable field, not the revisioned results list. `context` and `settings` contain model-specific JSON and may be empty; preserve unknown keys.

For clients explicitly authorized to edit results, `POST /api/cuts/{cut_id}/analysis-results` creates a result and `PUT /api/analysis-results/{result_id}` appends a human revision. Results have no approval status. Editing an already superseded revision returns 409. Deleting an individual current revision restores its parent as current when one exists.

For clients authorized to cancel work, `POST /api/jobs/{job_id}/cancel` cancels queued inference jobs and queued or running summary jobs. Running summary cancellation discards its result and frees the local worker; the remote provider may continue processing an already submitted request. Other running pipelines cannot be cancelled through this endpoint.

The episode brief endpoint returns each cut’s current `production_brief` (Cut summary Markdown, result ID, origin, model, job and creation time), or null when unavailable. Existing summaries remain available and may predate the production brief format. Cut and transcript source timestamps are episode-relative; the generated brief requests clip-relative timing. The export snapshots the same brief. Saved human answers and corrections are included in future queued generations; each job retains its own request snapshot. The model receives text evidence, not original audio.


**Context items** are project-wide when `episode_id` is null, otherwise episode-specific. Items include character, world, scenario, object, chapter, and general notes. **Transcript segments** have episode-relative time ranges, text, a deletion marker, and optionally `character_context_id`, linking to a character context item. Default episode transcript reads and cut detail include current non-deleted segments; segments can extend outside the cut. `history=true` on transcript returns all revisions including deleted. A **voice sample** links to a character through `character_context_id`; it can come from uploaded audio or one or more episode ranges. `preview_available` indicates whether its reference audio is currently available. Match IDs, not names. Its WAV reference is not necessarily a transcript of the cut.

## Recommended read sequence

1. Check `GET /api/health`. List `GET /api/v1/projects`, select the project by ID, then `GET /api/v1/projects/{project_id}/episodes` and select an episode by ID. Duplicate names are possible. Read `GET /api/v1/episodes/{episode_id}` for duration, dimensions, status, and `has_audio` (null before probing). Preparation or detection may still be running or failed. Check `GET /api/episodes/{episode_id}/status` for current job state.
2. List `GET /api/v1/episodes/{episode_id}/cuts?offset=0&limit=100`; follow `next_offset` until null. Active cuts only are returned by default. Use `include_archived=true` to include archived cuts after active ones. For CUT1 select the active item with `cut_index=0`. Pagination reflects live data and can shift if cuts are edited while paging; repeat the read if a consistent snapshot matters.
3. Call `GET /api/v1/cuts/{cut_id}`. It includes project and episode metadata, the cut, current analysis results, applicable context, overlapping transcript and chunks, adjacent cuts, project voice samples and relative links to media and further reads. Empty arrays mean no matching data is currently available, not that analysis succeeded. The response is a convenience aggregation rather than a transactionally consistent snapshot: refresh when editing is concurrent.
4. For full result revision history call `GET /api/cuts/{cut_id}/analysis-results?history=true`; the default is current revisions. Set `include_context=false` to omit potentially large captured evidence. For full transcript use `GET /api/episodes/{episode_id}/transcript` (or `?history=true`). `GET /api/cuts/{cut_id}/analysis-context` also supplies current results from neighboring cuts. `GET /api/projects/{project_id}/context` returns all project and episode-scoped context items; filter `episode_id` yourself when needed. `GET /api/cuts/{cut_id}/analysis-config` shows the current analysis settings. Job IDs in results or the episode's jobs list can be passed to `GET /api/v1/jobs/{job_id}` to inspect the queued input snapshot and any retained intermediate cut evidence. Snapshots can be large, can represent older data, and do not imply a job succeeded.
5. To fetch a character's reference, find a matching `character_context_id` in `voice_samples`, check `preview_available`, then download `GET /api/voice-samples/{sample_id}/audio`. `GET /api/v1/voice-samples/{sample_id}` also returns metadata and the stored model-specific voice embedding. Do not assume every character has a sample. To obtain cut audio, use `GET /api/v1/cuts/{cut_id}/audio?before=1&after=3`. This returns prepared mono 16 kHz PCM WAV from the original's first audio stream, with up to one second before and three seconds after the cut. Each margin is non-negative and at most 3600 seconds. The excerpt is clipped to the episode and available audio; `X-Audio-Start-Seconds` and `X-Audio-End-Seconds` are the actual sample-aligned episode timestamps. Archived cuts can also be requested. No audio, not-yet-prepared audio, or unavailable files return 404; an excerpt with no samples or invalid prepared audio returns 409; an excerpt exceeding WAV size limits returns 413. Do not assume silent video has an audio file.
6. For a cut's default image, download `GET /api/cuts/{cut_id}/frame/first`. The brief's `suggested_frame_url` points to this first frame when the original, proxy, or a saved first-frame thumbnail is available; it is not a model recommendation. The boundary endpoint can recreate a JPEG from the video, and temporary extraction failures return 503. Use `/last` for the other boundary or `GET /api/analysis-results/{result_id}/frame` to inspect a particular analyzed frame. Original video, proxy, or prepared whole-episode audio can be fetched through `GET /api/episodes/{episode_id}/media/original`, `/proxy`, or `/audio`. `GET /api/episodes/{episode_id}/frames` lists interval frames, and `/waveform` returns waveform data. The existing `GET /api/episodes/{episode_id}` also returns all active and archived cuts, chunks, job metadata, and preparation settings; it can be large.

## Example

```sh
BASE=http://192.168.0.6:8080
curl "$BASE/api/v1/projects"
curl "$BASE/api/v1/projects/PROJECT_UUID/episodes"
curl "$BASE/api/v1/episodes/EPISODE_UUID/cuts?limit=100"
curl "$BASE/api/v1/cuts/CUT_UUID"
curl "$BASE/api/cuts/CUT_UUID/analysis-results?history=true"
curl -o first-frame.jpg "$BASE/api/cuts/CUT_UUID/frame/first"
curl -OJ "$BASE/api/v1/cuts/CUT_UUID/audio?before=1&after=3"
curl -o voice.wav "$BASE/api/voice-samples/VOICE_SAMPLE_UUID/audio"
```

Replace placeholders with returned IDs. Quote URLs containing `&`. JSON errors use `detail`; HTTP 404 means the requested object or media is absent, 409 indicates a state conflict, and 422 indicates invalid parameters. Available data and URLs can change after edits, deletion, or reruns. Media downloads can be large. Polling and caching clients should retry according to their own needs and respect failed job states. The `/api/v1` integration endpoints are read-only; the existing `/api` also contains mutating endpoints. Do not invoke mutations unless explicitly requested.

## Agent-ready briefs and downloads

`GET /api/cuts/{cut_id}/structured-analysis` returns structured single-cut outputs as JSON objects, including their type, source and revision links. Pass `?history=true` for all revisions. The brief's `initial_frame` includes the current structured initial-frame result when available. A missing result means it has not yet been generated; do not infer one from a legacy summary. Editing an existing structured result through `PUT /api/analysis-results/{id}` requires `content` to be a JSON object encoded as a string, and creates a new revision.

Single-cut runs produce structured `initial_frame`, `video_analysis`, `last_frame` and `subtitle_ocr` results. New visual-only runs do not automatically queue text processing. `POST /api/episodes/{episode_id}/visual-analysis` queues individual visual jobs for enabled cuts; the older `/api/episodes/{episode_id}/analyze` route is a visual-only alias and returns all `job_ids` plus the first `job_id` (or null if nothing was queued). Batch queueing skips cuts with queued or running visual jobs; a single-cut request for an already queued cut returns 409. Queue a separate `consistency_summary` with `POST /api/cuts/{cut_id}/consistency-summary`, or queue consistency and dependent briefs for ready enabled cuts with `POST /api/episodes/{episode_id}/text-processing`. Jobs queued under the earlier workflow retain their original automatic behavior. Its visual and transcript inputs are captured at queue time; the result contains source IDs and a snapshot of the evidence. Its separate job can fail even when visual analysis succeeded. A newer summary revision blocks an older queued job from overwriting it. `GET /api/cuts/{cut_id}/analysis-stages` lists stage attempts, errors, and elapsed seconds; interrupted attempt times use the last worker heartbeat. Read stage state and job status before assuming a run completed.

Video analysis accepts any valid JSON value, so its structure may vary. When an event has a usable in-window interval, derived episode-relative timestamps accompany the model’s clip-relative times. Model-provided times are unverified and may be unordered, overlap, or fall outside the window; they are retained rather than rejected. Long cuts are partitioned into analysis windows, so events crossing windows can be split. Visual models process silent video and cannot establish who is audibly speaking; speaker and character links come from transcript evidence and need verification. Subtitle OCR runs only when a transcript overlaps the cut, and readings are model predictions. OCR observation times are sampled frame times rather than exact subtitle or speech boundaries; language can be `unknown`. Text is reference evidence and should not be reproduced as visual content.

`GET /api/jobs/{job_id}/analysis-windows` returns the recorded source timing, preparation settings, model revision and structured output for each completed video window, including windows saved by an incomplete run. Retry copies these checkpoints and uses them when their timings and model revision still match. Temporary video files can be removed without losing the metadata or observations.

In the composition view, adjacent near-identical OCR readings in the same language may be grouped as one subtitle line. Its `t` is the first sampled observation and its text is the latest reading in that group; it is not an exact subtitle start time.

Use `GET /api/v1/episodes/{episode_id}/brief?from=1&to=14` for an inclusive range of one-based active cut numbers (maximum 500). Each cut includes episode-relative `[start_time, end_time)` timings, IDs, current overlapping transcript segments with speaker labels and character context IDs, model-generated production sections with qualitative confidence, and relative audio and first-frame URLs. Transcript segments crossing a cut retain their original boundaries. Empty dialogue does not prove silence. Null sections and `unavailable` explain missing data; run visual analysis again to populate structured fields for older summaries or summaries edited as free text. The action beats and character descriptions are model-generated observations and may be uncertain; use source media for verification.

### Composition view (in development)

`GET /api/v1/episodes/{episode_id}/brief?from=44&to=68&view=composition` projects the saved visual results, transcript, OCR and character detections into cut records. It does not invoke a model. `shot` uses standardized shot-size, angle and camera labels when they can be extracted; `subjects`, clip-relative `beats`, `end_state`, merged `dialogue`, sampled `subtitles`, `issues` and detection `links` are based on existing observations and may be incomplete or incorrect. Detection boxes use the source frame's pixel coordinates. Each link groups first-frame and last-frame boxes as separate arrays; array order does not pair unnamed people across frames. A link's zero-based `subject` index points into the cut's `subjects`, which carries its `character_context_id`; when no unique opening subject matches, a known link instead carries `character_context_id` directly. If `fields` excludes `subjects`, links carry character IDs directly. `identity` distinguishes confirmed user labels from likely matches. Subtitle `t` is an observation time, not an exact subtitle interval. `unavailable` values are short codes explained by the range's `unavailable_reasons`; `bp` means beat timing or content is missing, and `sp` or `lp` means some setting or lighting detail could not be kept within its word limit. The current projection may omit details and exceed the intended 2 KB-per-cut target; it is not yet a complete composition contract.

`duration` is the cut length in seconds. Beat and utterance times are relative to the cut start. The default omits episode-relative boundaries; request them with `fields=start_time,end_time` when needed. `ready_count` and `pending` refer to the entire requested range. An unready cut contains identity and readiness metadata rather than a partially populated shot. `only_ready=true` filters unready cuts. `updated_since` accepts a timezone-aware ISO 8601 timestamp and is inclusive at millisecond precision, so deduplicate repeated records by cut ID and `analysis_rev`. When projection code changes, startup advances cut watermarks so an incremental reader can discover changed output; unchanged records may be returned again. The response is a database snapshot; file availability can change independently. `fields=shot,dialogue` selects cut keys, retaining `id`, `cut_number`, `ready`, `updated_at`, and `analysis_rev`. `include=` accepts comma-separated `initial_frame`, `last_frame`, `video_analysis`, `subtitle_ocr`, `consistency_summary`, and `dialogue_segments` to add the original structured results or overlapping segments. Includes can greatly increase the response size. Invalid names return 422.

Dialogue is preserved even when it makes a cut exceed the size target. In particular, a single transcript segment can itself be larger than 2 KB; the composition view does not truncate it to meet the target.

Treat `analysis_rev` as an opaque equality token; its encoding can change between releases. `unavailable.beats_partial` is present when the beat timeline is incomplete.

In `beats` and `end_state.subjects`, an integer `subject` is a zero-based index into the same cut's `subjects`; a string identifies a subject that cannot be linked uniquely. With `fields` that excludes `subjects`, those indices are expanded back to names so the selected fields remain self-contained.

Depth defaults to `mid` when the source does not specify a depth. The end-state comparison does not treat a change to or from that default as established movement; it marks the end state partial when the depth change is uncertain.

Use `/api/analysis-results/{initial_frame_id}/frame` for the analyzed first-frame JPEG, `/api/analysis-results/{last_frame_id}/frame` for the last, and `/api/v1/cuts/{id}/audio` for the exact-cut WAV. URLs are relative to the server origin. A missing audio or frame file can still yield 404 or 503. The `view`, `include`, `fields`, `only_ready`, and `updated_since` parameters also apply to the export POST. Composition exports contain `cut-NNNN-UUID-initial.jpg` at 1280×720 and, with `include=last_frame`, `cut-NNNN-UUID-last.jpg`; the manifest reports extraction errors, `audio_seconds` when audio was extracted, and `has_speech` based on current overlapping transcript segments. Exports run independently of episode analysis jobs and are excluded from cancellation of queued analysis jobs.

To retrieve the brief and assets together, `POST /api/v1/episodes/{episode_id}/brief/exports?from=1&to=14`, then poll `GET /api/v1/brief-exports/{job_id}` until it is `done` or `failed`. Download the returned `download_url` when done. The ZIP contains `brief.json`, `manifest.json`, per-cut sample-aligned WAV audio (including cuts shorter than two seconds), and suggested composition JPEGs when available. The manifest records missing assets and extraction errors. The brief is snapshotted when the export is queued; assets may become unavailable before processing. Audio is from prepared episode audio, and silent episodes do not provide WAV files.

Local and OpenRouter text outputs record `settings.provider` (`local` or `openrouter`), `settings.summary_generation_seconds`, optional `settings.usage` token counts and, for the pinned local model, `settings.model_revision`. These values are absent for older runs or where the provider did not supply usage; do not infer token counts from text length. Visual results use `provider: local` and may record `generation_seconds` and model token counts when available.
